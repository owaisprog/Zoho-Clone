Five implementation slices: persistent receipts; bounded CSV parser, normalized row isolation and synchronous deduplication; localhost-only public token route and consent/honeypot/quota; typed client and React upload/preview/status/capture; SQL/HTTP/browser tests.
Import is restricted to active sales reps in the disposable fixture. Required CSV headers may be reordered; single-line quoted fields supported, 20 rows max, no multiline values or arbitrary mapping. Invalid cells are normalized to null and never persisted; receipt digest binds normalized rows. No raw upload storage. Deduplication follows the existing tenant/owner email constraint. Capture token is hashed at rest, fixture-provisioned, tied to active owner identity, origin constrained to localhost, requires consent and empty honeypot; at most 20 successful new submissions per token. Exact request replay returns identical generic receipt; no public tenant information returned. No real public route, no external email, no live migration, no deployment, no paid service.
