# R91 — integrated isolated recovery rehearsal

Five slices: snapshot all six current UUID platform schemas (16 tables) and compare canonical row digests; real custom-format pg_dump/pg_restore into a distinct disposable database; preserve RLS and restricted login permissions; reconcile a known post-snapshot membership revocation and invalidate restored download grants before resuming; verify exact pending job cancellation/delivery-once and unchanged source database. The test fixture intentionally shows why a restored snapshot is not immediately safe to serve traffic. The recovery reconciliation is specific to a known synthetic revocation, not a complete production transaction journal, PITR or cross-provider failover. Restored roles are present in the same disposable cluster. The worker tests use the restricted exact-job SQL function; no Redis state restoration is necessary or claimed because PostgreSQL is authoritative. Archive stays in memory. Timings describe CI dump/restore only, not production RTO or RPO.

## Remaining staging authorization

Do not deploy this candidate or run any Neon migration. Actual staging needs approved infrastructure/region/budget, isolated Auth0 and DB accounts, restricted credentials, private storage/scanner, migration compatibility, artifact/config backups, a complete revocation and post-backup change reconciliation plan, paused ingress/workers, and reviewed rollback/RPO/RTO. Cross-tenant restore checks and formal acceptance must precede traffic. No production credentials or provider changes, no owner acceptance. All ten gates OPEN.
