# R87 — durable notification queue bridge
Five slices: exact pinned BullMQ and Playwright preparation dependencies with CI-resolved npm lock; restricted due/exact-job PostgreSQL functions; actual disposable Redis/BullMQ dispatch and worker with opaque tenant/event/attempt job envelope; replay, cancellation and dispatcher restart integration tests; documented boundary. PostgreSQL remains the source of truth and checks membership, role, record, revision and entitlements on delivery. Dispatch is explicitly invoked and bounded, not scheduled; Redis is only a wakeup transport. Failed DB deliveries remain in PostgreSQL for later due polling, not independent queue retries. No production Redis, queue credentials, mail/SMS, live jobs or deployment. Browser dependency is pinned for R89; browser execution not yet claimed. CI verifies local transport restart, not a real provider outage or production recovery. Formal gates OPEN, NO_GO.
